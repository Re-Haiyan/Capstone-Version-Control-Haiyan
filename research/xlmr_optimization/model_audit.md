# Model audit: which sentiment model runs, and where it came from

All hashes are in `results/inventory.json` (generated by `inventory.py`). Nothing in the repository, on the VM or in a model file was changed.

**Not in production:** the `sentiment-blend` branch of the repository (commit `fb37363`, not an ancestor of production). It adds a "sentiment blend" (0.6 shipped model + 0.4 logistic head on the encoder's embedding), review heads, and a combined dataset whose own manifest labels 9,999 of 20,525 rows **AI silver**. It is neither deployed nor evaluated in this study; any use of it needs its own audit. The hazard-flag models in `training/runs/v1..v3` are XLM-R models fine-tuned for defect, counterfeit, safety and similar **flags**, not for sentiment: they are a different task and are not candidates here.

## 2. Architecture and artifact

* XLM-RoBERTa base encoder (12 layers, hidden 768, about 278 M parameters including the 250 k-token embedding table), three-way classification head, label order `negative, neutral, positive`, maximum sequence length 128 (truncation), raw review text (no normalisation), SentencePiece tokenizer shipped as `tokenizer.json`.
* The production artifact is an **ONNX int8 dynamic-quantised** graph (`stage: onnx_int8`) with a second output `hidden_states` added later for the hazard classifiers (`sentiment_unchanged_check`: 3,617 texts, 0 label changes, max logit difference 0). It is scored one review at a time because the int8 activation scales depend on the batch.
* Manifest: `model_version defaketive-xlmr-firecs-v1-onnx-int8-e04da4c2`; recorded scores FiReCS test macro F1 0.833, "marketplace" macro F1 0.7064; gate "marketplace macro F1 >= incumbent + 0.02".

## 3. Checkpoint provenance

* `source_checkpoint` in the manifest names `cardiffnlp/twitter-xlm-roberta-base-sentiment` (a public multilingual Twitter sentiment model). That public FP32 checkpoint **is on this machine** (Hugging Face cache, snapshot `48de035c...`, `model.safetensors` 1,112,212,292 bytes, SHA-256 `0c0d65e6a3ff...`).
* **The deployed model is not that checkpoint.** Zero-shot, the public checkpoint scores 0.639 macro F1 on FiReCS test against 0.833 for the deployed model, and the two models give the same label on only 72.8% of FiReCS test reviews (mean absolute probability difference 0.21). The deployed model is therefore a **fine-tuned** derivative (consistent with the name `xlmr_firecs_v1`), compressed to int8.
* **The fine-tuned full-precision checkpoint is missing.** No FP32 or pruned fine-tuned sentiment checkpoint, no fine-tuning script, no training log and no slimming report (`research/slimming_xlmr_firecs_v1.json`, named in the manifest) exists in the repository, its history, `D:/defaketive-train` or this machine's caches. The hyper-parameters and data of the original fine-tuning (learning rate, batch size, epochs, optimizer, seed, whether FiReCS only) are **unknown**. The manuscript was not available.
* Consequently the historical rows 0.846 (original), 0.847 (pruned), 0.847 (ONNX FP32) and their marketplace figures (0.719, 0.722, 0.722) **cannot be reproduced**: their artifacts do not exist here. Only the shipped int8 row can be, and it was (`baseline_results.md`).

## 4. What this study could and could not reproduce

| Historical figure | Reproduced? |
|---|---|
| Shipped int8, FiReCS test macro F1 0.833 | **Yes, exactly** (accuracy 0.833, macro F1 0.833; `results/metrics__onnx_int8__firecs_test.json`) |
| Shipped int8, marketplace macro F1 0.706 | **No, not located.** The 300 older team-labelled reviews (`gold_labels_200`, `heldout_labels_100`) give 0.822 on the 226 high-confidence rows and 0.758 on all 300; the marketplace file that gave 0.706 is not identifiable. |
| Later 846-row evaluation, about 0.586 | Reproduced approximately: 0.570 macro F1 on the 846 high-confidence rows with the raw model (0.586 in `research/evaluation_report.md` used the rows that also have a flag label and the pipeline's output) |
| Original, pruned, ONNX FP32 rows | **No: artifacts missing** |

Differences between the reproduced numbers and the older ones come from different evaluation files, different row filters and different label sets, as the brief warned; they are not interchangeable.

## 5. Training data provenance (as far as it can be established)

* FiReCS (Cosme and De Leon 2024, CC BY 4.0): 7,340 training and 3,147 test reviews, labelled by the dataset's authors; hashes match the published values. Whether the deployed model was fine-tuned on all of FiReCS train alone is **not recorded**.
* Every marketplace label in this repository is a **team-supplied label of unverified provenance** (`research/annotation_provenance.md`); the 10,000-review pool of the `sentiment-blend` branch carries AI silver labels. **No independent human-verified marketplace sentiment set exists.**

## 6. Deployment resource requirements (existing measurements, same VM, `research/results/bench_vm_final/`)

Cold start about 2.1 s, memory after load about 370 to 400 MB (peak 375 to 405 MB), single-review median about 62 ms (p95 134 ms), about 14.4 reviews per second with the whole checker, model files 100 MB in total, VM 2 vCPU and 3.8 GB.
